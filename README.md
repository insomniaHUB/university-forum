# Техническое задание: «Форум для студентов вуза»


## Технологический стек
* **Frontend:** HTML5, CSS3, JavaScript (React)
* **Backend:** Node.js (Express / NestJS)
* **Database:** PostgreSQL

## Общие требования
1. **Интуитивный интерфейс:** Приложение должно иметь интуитивно понятный интерфейс, адаптивный дизайн и обеспечивать удобный доступ к обсуждениям.
2. **Медиафайлы:** Возможность публикации текстовых материалов, а также прикрепления изображений (PNG, JPG).
3. **Кроссбраузерность:** Поддержка минимально необходимых версий браузеров:
   * Chrome >= 60
   * Firefox >= 55
   * Edge >= 79
   * Safari >= 12

## Функциональные требования

### 1. Навигация и структура форума
* Главная страница содержит список категорий (например: *«Общие вопросы», «Факультеты», «Доска объявлений», «Учеба и материалы»*).
* При клике на категорию открывается список соответствующих тем (веток обсуждения) с пагинацией (постраничным выводом, например, по 20 тем на страницу).

### 2. Фильтрация и сортировка
Пользователь может упорядочить список тем по нескольким критериям:
* По дате создания (сначала новые).
* Фильтрация тем по выбранному тегу (категории).

### 3. Базовые операции и бизнес-логика

#### Авторизация и разделение ролей
* Регистрация пользователей с обязательными полями: Имя, Email (проверка на валидность), Пароль.
* Ролевая модель:
  * **Студент:** Может создавать свои темы/комментарии, редактировать и удалять их, просматривать чужие посты.
  * **Преподаватель:** Обладает всеми правами студента + имеет расширенные права модератора (удаление любых некорректных комментариев или тем в рамках своего предмета/курса).

#### Управление контентом (CRUD)
* Полноценная реализация операций: Create (Создание), Read (Чтение), Update (Редактирование автором), Delete (Удаление автором или преподавателем).

#### Отображение комментариев
* Последовательный (линейно-хронологический) вывод комментариев внутри темы от старых к новым.

#### Система внутренних уведомлений
* Реализация через базу данных.
* Уведомление генерируется на бэкенде и отправляется студенту в случаях, когда:
  * Кто-то оставил комментарий в созданной им теме.
* На фронтенде в шапке сайта отображается иконка колокольчика с индикатором количества непрочитанных уведомлений.

#### Модерация контента
* Преподаватели имеют доступ к кнопке «Удалить» на любом комментарии или теме.

### 5. Поиск
* Текстовое поле поиска в шапке форума.
* Бэкенд выполняет поиск совпадений по ключевым словам.


## Дополнительные функциональные требования (необязательно)

1. **Социальные элементы и рейтинги:**
   * Возможность поставить «Лайк» или «Дизлайк» теме или комментарию.
   * Вывод блока «Популярное за неделю» на главной странице на основе формулы: количество лайков + количество комментариев за последние 7 дней.
2. **Сессии и сохранение состояния:**
   * Аутентификация на базе **JWT (JSON Web Tokens)** или сессионных кук.
   * Токен сохраняется на клиенте в `LocalStorage` или безопасных `HttpOnly Cookies`.
   * При перезапуске браузера фронтенд считывает токен, отправляет запрос на эндпоинт `/api/auth/me` и автоматически восстанавливает авторизованную сессию пользователя без повторного ввода логина и пароля.
3. **Закладки и подписки:**
   * Кнопка «В избранное» внутри темы. Позволяет сохранить ссылку на ветку в личном кабинете студента.
   * Функция подписки на тему: включение пользователя в список рассылки уведомлений для конкретной ветки, даже если он не является её автором.
